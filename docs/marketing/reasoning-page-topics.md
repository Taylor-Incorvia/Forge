# Website "reasoning" page — topics + framing (2026-09-08)

Notes for the wildcardarena.com **"why the design intentionally clashes with standard RTS"** page.
The website is a **separate repo/agent** — this doc is source material, not the page itself.
Low-traffic page by design (it's a *point-people-to-it* credibility asset, not a discovery page —
~10 of 980 loads landed here; that's fine for its job). Don't over-invest; do keep it *correct and sharp*.

## What the page already covers
1. Depth without a memorization wall (adaptation beats memorized build orders; skill available game 1).
2. No stale meta (new faction every game → no standardized builds).
3. Per-unit balance, not per-matchup balance (faster, easier-to-explain balance).
4. Noticeable upgrades over invisible ones (visible rolled upgrades vs +1/+1; **no Engineering Bay**).

## Recommended topics to ADD (priority order)
1. **Clarity is the constraint** — the biggest gap. Why there's **no Warp Gate, no Larva, no asymmetric
   economy**, and a **mirrored economy** so you can scout the enemy and compare directly to yourself.
   No "army teleports into my base" mechanics because they're unreadable in a randomized-faction game.
   Natural big sibling to the existing "no Engineering Bay" beat. Makes the design read as *intentional*
   rather than arbitrary.
2. **"Is it just luck?"** — disarm the #1 competitive-player objection head-on: mirrored economy, both
   players face the same uncertainty, and *adaptation* is the skill that decides it. Highest credibility
   payoff of any topic.
3. **Attention is a resource** (the "simple game plan effect", player-positive framing) — easy-to-use
   units cost more because the attention you don't spend on your army goes into macro. Frame as an elegant
   insight, NOT the internal "single-unit-mass is a trap" (which reads as punitive to a newcomer). Draw from
   `docs/design-principles.md` → "The Simple Game Plan Effect."

Topics 2–4 all orbit "adaptation" — pick the two sharpest rather than run all three and dilute. Best bets to
change a skeptic's mind: **#1 (clarity is intentional) and #2 (not a coin flip).**

## Genre framing
Taylor is claiming the sub-genre name. Working candidates: **"Roguelike Competitive RTS"** (the *Competitive*
is the axis that separates it from single-player roguelike RTS like Rogue Command — a live opponent + a new
faction every game means there's no solved build to fish for). "Roguelike RTS" may hook a broader audience
faster than "Wildcard RTS." His call. See the `project-wildcard-rts-design-thesis` memory for the full thesis.

## Framing rule
Internal design docs state rules as constraints ("keep mass units underpowered", "single-unit-mass is a
trap"). On a public page, flip to the elegant-insight version — same idea, sounds *thoughtful* not *strict*.
